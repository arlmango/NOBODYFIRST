# Fault injection: fixture tests, expected errors and emitters

Source: `test/Level1FaultInjection.t.sol` (12 tests, all pass in `fault-injection.log`, `EXIT=0`, generated by `scripts/run-stage2.sh` with `forge test --match-contract Level1FaultInjection -vvv`). Fixtures: `test/harness/FaultFixtures.sol`. Production `src/` is unmodified.

## Header of the test file (quoted)

> FAULT INJECTION: coordinator/NPC defensive checks that an honest deployment never trips.
> Production src is unmodified. Faults come only from test/harness/FaultFixtures.sol:
> NPC_B subclasses (override virtual `release` only), standalone INpc fixtures (slot B or C),
> and ledger probes installed with vm.etch over the production GameItems address (same
> storage layout, checked by reading the pre-etch balances back through the probe).
> Wiring with fixtures is built here with vm.computeCreateAddress (like Level1LateFailure);
> tests with ledger probes use the unmodified Level1Deployer wiring.
> Shared selectors (Reentrancy, UnknownOffer, InvalidNpc, PlanRejected) are pinned to the
> originating contract with vm.expectRevert(bytes, address reverter).

Header of the fixture file (quoted): "Each fixture has exactly one unconditional fault (no switches/flags)." Fixtures are never deployed by `Level1Deployer`.

Notes on the table, from the source:
- `OBSERVER_TOUCHED` = 10 is defined in `src/Types.sol:58`. The fixture uses it directly. The header lists "NpcBase rejection code 10 OBSERVER_TOUCHED" among the checks that are not reachable with production NPCs.
- `test_Fault_PermitConsumedBeforeLedgerCall` has a comment in the source: "(Reviewer mutant M01 — delete moved after the ledger call — makes this test fail.)" That is the test author's note; the mutation results are in `mutation-results-author.txt`.
- The `test_Fault_PermitOrderProbe_DetectsActivePermit` test is the check that the probe itself is not vacuous (the source comment says: "The probe is not vacuous: a ledger call while the caller holds an active permit reverts.").

## Checks that cannot be reached (quoted from the test header)

> Checks NOT reachable with any honest or faulty NPC/ledger we can build without editing src:
> * AtomicCoordinator.ConservationViolated: _simulate subtracts and adds the same qty of the
>   same item for every transfer, and InvalidTransfer already guarantees item in {KEY, COIN}
>   and npc ids in range, so per-item sums are equal by construction (defence in depth).
> * AtomicCoordinator.RunNotActive: every run is created active and becomes inactive only
>   together with solved=true, which AlreadySolved (checked first) reports.
> * NpcBase rejection code 10 OBSERVER_TOUCHED: codes 7 (C sends) / 6 (C receives) fire first.
> * NpcBase rejection code 8 via execute: the coordinator's InsufficientStock (step 5) fires
>   before any NPC validates (code 8 is covered by direct validatePlan in Level1Exchange).
> * Level1Deployer.PredictionMismatch / UnsupportedNonce: CREATE addresses are deterministic
>   and the constructor only uses nonces 1..5.

Status of those items in this evidence:
- The header states these checks are unreachable. The grep in `forbidden-grep.log` does not test reachability; reachability is the test header's argument, not a result recorded here.
- Correction (documentation pass): the header bullet on code 8 says it is "covered by direct validatePlan in Level1Exchange". That is wrong. Code 8 (`INSUFFICIENT_STOCK`) is tested by direct `validatePlan` in `test/Level1NpcValidation.t.sol:102-103`; `Level1Exchange.t.sol` has no code-8 test. The header's claim that code 8 is unreachable through `execute` is correct (the coordinator's `InsufficientStock` fires first, `src/AtomicCoordinator.sol:285`).
- Correction (documentation pass): the statement that `NpcBase` code 10 "is reached only through the standalone fixture `RejectingObserverC`" is inaccurate. The `NpcBase` branch (`src/NpcBase.sol:263`) is **not** executed by any test. `RejectingObserverC` (`test/harness/FaultFixtures.sol:123-127`) raises `PlanRejected(NPC_C_ID, OBSERVER_TOUCHED)` itself, so the test `test_Fault_RejectingObserverC_PlanRejectedFromC` does not exercise `NpcBase` code 10. See `GUARANTEES.md` sections 3 and 4.
