# NOBODY FIRST, stage 2 contracts (level 1)

Scope: the level-1 contracts (`src/`), their tests (`test/`), and the evidence in `evidence/contracts/`. Not in scope: levels 2 and 3, UI wiring, a security audit.

What is guaranteed, by which contract, and how far the evidence goes: [`evidence/contracts/GUARANTEES.md`](evidence/contracts/GUARANTEES.md). The guarantees apply only to the set deployed by `Level1Deployer`, not to other contracts that implement the same interfaces.

## Prerequisites

Tools are already installed in `contracts/.tools` (forge, cast, anvil 1.8.5; solc 0.8.37 at `.tools/solc/solc-0.8.37`). Nothing is downloaded: `foundry.toml` sets `offline = true` and the pinned solc. Run all commands from `contracts/`.

## Commands

> **Warning: these commands write outside the project.** Every `forge` command (including `scripts/run-stage2.sh`, which runs forge) writes to the global cache `~/.foundry/cache/signatures`, which is outside `contracts/`. Writing it was not permitted; this is a known violation of the write boundary and is not authorised after the fact. No documented way to move that cache into `contracts/.tools` has been found. Decide first whether this write is acceptable. Details: `evidence/contracts/GUARANTEES.md`, section 8.

```bash
# one run of everything, into a folder of your choice (no anvil unless --anvil is given)
scripts/run-stage2.sh <output-dir>

# same, plus a local Anvil deployment on 127.0.0.1:8599 (chainId 31337; anvil is killed at the end,
# its own output is discarded because it prints dev keys)
scripts/run-stage2.sh <output-dir> --anvil
```

The script runs, in order: `forge build --force`, `forge build --sizes`, `forge test -vv` (all 7 suites, 77 tests), `forge test --json`, one `-vv` run per suite, the late-failure trace (`-vvvv`) and tables (`-vv`), the happy-path test (`-vvv`), setUp traces (`-vvvvv`, happy path and wiring), the fault-injection suite (`-vvv`), the two source greps, the optional Anvil section, and the signature-cache size and hash before and after. It writes `exit-codes.txt` with one line per step. Exit status is 0 only if every required step exits 0.

Individual commands:

```bash
./.tools/bin/forge build --force
./.tools/bin/forge build --sizes
./.tools/bin/forge test -vv                                       # 77 tests, 7 suites
./.tools/bin/forge test --match-contract Level1LateFailure -vvvv  # late-failure trace
./.tools/bin/forge test --match-contract Level1FaultInjection -vvv
./.tools/bin/forge inspect <Contract> methodIdentifiers           # ABI selectors (see abi-selectors.log)
```

The Anvil deployment, done by hand, is the same as the `--anvil` branch of the script: start `./.tools/bin/anvil --host 127.0.0.1 --port 8599`, then `forge create src/Level1Deployer.sol:Level1Deployer --rpc-url http://127.0.0.1:8599 --unlocked --from <account0> --broadcast`, then `cast call`/`cast send` as in the script. `--unlocked` means no private key appears on any command line.

## Known limits

- Not an audit. No security review has been done.
- Trust boundary: each guarantee holds only for the wiring `Level1Deployer` creates. In `authorize`, NPC A and B check `before` themselves against the live ledger (`src/NpcBase.sol:147-151`). `validatePlan` uses whatever `before` it is given; inside `execute` that is the coordinator's own live read (`src/AtomicCoordinator.sol:130`), and NPC_C is checked only this way. `snapshotHash` and `planHash` are taken from the coordinator, stored as given and compared for equality only (`src/NpcBase.sol:153,164`). `validatePlan` and `isGoalSatisfied` are views that judge only the arguments passed in (see `evidence/contracts/GUARANTEES.md`, section 2).
- Foundry cache write boundary: forge writes `~/.foundry/cache/signatures` outside the project. This is a violation that was not permitted; the file was not deleted (`GUARANTEES.md`, section 8).
- Mutation testing: the final suite (77 tests) kills 30 of 31 reviewer mutants; M06 (drop the ConservationViolated check) survives. `ConservationViolated` is reached by no test and is argued to be unreachable (test header `test/Level1FaultInjection.t.sol:16-18` and the reviewer's reasoning; not a test result) (`GUARANTEES.md`, section 5).
- The Anvil late-failure receipt is the reviewer's manual replay on a local chain, not produced by the script, and its Anvil state is gone (`GUARANTEES.md`, section 6).
- No UI wiring. The frontend is not connected to these contracts.
- One run per player: `startRun` uses the caller address as the run id; a player's second run reverts `RunExists`.
- No reset: there is no function to clear a finished run or redeploy the level in place.
- No levels 2 and 3.
- Level1Deployer initcode is 48,084 B against the 49,152 B EIP-3860 limit (margin 1,068 B, about 2.2 %, `sizes.log`). Each NPC's creation code is embedded in the deployer, so any growth in `NpcBase` is multiplied (`GUARANTEES.md`, section 7).
- The optimizer is off: `foundry.toml` sets no optimizer option (Foundry default). Build products under `out/` (not in the evidence folder) record `"optimizer":{"enabled":false,"runs":200}`, observed by grep in the documentation pass.
- NPC trusts coordinator-supplied hashes: `authorize` and `release` take `snapshotHash` and `planHash` from the coordinator. The permit binding is a consistency tag, not an independent check of the snapshot.
- Unreachable checks (per the test header, `test/Level1FaultInjection.t.sol`): `AtomicCoordinator.ConservationViolated`, `AtomicCoordinator.RunNotActive`, NPC rejection code 10 with production NPCs, and `Level1Deployer.PredictionMismatch` / `UnsupportedNonce`.
- Anvil results come from a local chain (chainId 31337). They are not from a public network.
